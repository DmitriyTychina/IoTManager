# Конечный автомат статусов устройств

> **Reference**. Логика — `_next_state` в `core/devices.py` (ранее в `app.py`).
> Папка устройства идентифицируется ключом `<имя> <id>`.

## Состояния

| Цвет | Значение |
|---|---|
| 🟢 Зелёный | Свежий multicast-пакет с совпадением имени и id устройства **ЛИБО** успешный пинг + актуальный `settings.json` с совпадением имени и id |
| ⚪ Серый | Статус не подтверждён: пинг успешен, но multicast не приходил / имя+id не совпадают, или данных нет |
| 🟡 Жёлтый | 1–3 провала пинга **после зелёного** (multicast не обновлялся) |
| 🔴 Красный | Более 3 провалов пинга (только после жёлтого) |

Переходы реализует функция `_next_state(cur, fails, confirmed, ping_ok)`
(юнит-тесты — `test_device_status_fsm.py`).

## Ключевые правила

- Жёлтый/красный достижимы **только после зелёного**; из серого в жёлтый/красный перейти нельзя.
- Повторное подтверждение (multicast или пинг+settings) сразу возвращает зелёный.
- Успешный пинг без подтверждения переводит зелёный/жёлтый/красный в серый.
- **Живой multicast авторитетен над `settings.json`**: при свежем multicast пинг и
  `settings.json` НЕ выполняются (на разделяемом IP settings может вернуть имя другого
  устройства; после переименования остаются старые папки с тем же id).
- Пинг выполняется **один раз на уникальный IP**; если папок на одном IP несколько,
  он проверяется единожды.
- На одном IP зелёным может быть **только одно устройство** (`_enforce_single_green`):
  при обнаружении нескольких зелёных папок с одним IP зелёным остаётся подтверждённая
  в текущем цикле, остальные переводятся в серый (защита от дублей/коллизий).
- После свежего multicast устройство не пингуется **70 секунд** (`PING_SKIP_AFTER_MULTICAST=70`):
  multicast идёт каждые 60 сек и сам подтверждает живость и идентичность.
- Во время скачивания файлов (`fetch` RAM/FS) пинг и WS-запросы к этому IP приостанавливаются
  (`_device_busy_fetching`), чтобы не срывать передачу.
- Источник идентичности при отсутствии multicast — `ws_client.fetch_settings(host)`
  (команда `/list|`, блок `settin`). Пинг (`_mark_device_seen`) НЕ обновляет
  `last_seen` multicast и зелёный не даёт.
- Имена устройств в вебе показываются без изменений (подчёркивания сохраняются) —
  в отличие от `dispName` проектов.
