> Пользовательская техническая документация. Описаны только те функции и факты,
> которые подтверждены в коде репозитория и документации (README, конфигурация
> `platformio.ini`, исходники `src/`, веб-панель `tools/magicIoTm`).
> Там, где информация отсутствует, стоит пометка *(уточнить)* или *не найдено в документации*.

## 1. Обзор проекта

**IoTManager** — это система «умного дома» на основе микроконтроллеров
**ESP8266** и **ESP32** (поддерживаются также платформы **ESP8285**, **ESP32-S2/S3/C3/C6/CAM** и чип **BK7231N**).

Микроконтроллер подключается к домашнему Wi-Fi роутеру, к его пинам можно
подключать разнообразную периферию: сенсоры, реле, шаговые двигатели, сервоприводы
и другие устройства. Прошивка позволяет **получать данные со всех этих устройств
и управлять ими**.

Управление возможно двумя параллельными способами, которые работают одновременно
и полностью синхронизированы:

1. **Мобильное приложение** (iOS/Android). Для связи используется MQTT-брокер:
   все устройства и приложение подключаются к нему через домашний роутер.
   Благодаря этому устройствами можно управлять из любой точки мира.
2. **Веб-браузер** — работает даже без Интернета. Все устройства доступны на одной
   странице.

Для старта достаточно трёх вещей:
1. купить ESP-микроконтроллер;
2. установить приложение;
3. получить облачный MQTT-брокер (например `wqtt.ru` или свой на Raspberry Pi).

Если удалённое управление и приложение не нужны — шаг 3 можно пропустить.

Логика каждого устройства настраивается **сценариями** — на любое действие можно
назначить любую реакцию (например: температура поднялась → выключить нагреватель;
влажность упала, а уровень в баке больше 10% → включить полив, иначе отправить
уведомление в Telegram).

Сопутствующие инструменты репозитория:

- **magicIoTm** — локальная веб-панель (Python Flask) для конфигурации проектов
  прошивки и управления устройствами;
- **measure_size** — скрипт замера размера прошивки (flash) по модулям;
- **PrepareProject / PrepareServer** — подготовка проекта к компиляции;
- **udp_multicast_listener.py** — сниффер multicast-UDP-пакетов устройств.

## 2. Возможности

Подтверждено кодом и документацией:

- **Прошивка для ESP8266 / ESP32 и совместимых платформ** (фреймворк Arduino,
  файловая система LittleFS).
- **Подключение к Wi-Fi** и к **MQTT-брокеру** (клиент `PubSubClient`, библиотека
  `PicoMQTT`; также есть модуль встроенного MQTT-брокера `BrokerMQTT`, порт по умолчанию 1883).
- **Локальный веб-интерфейс устройства** (HTTP, порт 80) и **WebSocket-сервер**
  (порт 81).
- **OTA-обновление прошивки** по сети (модули `UpdateServer`, `UpgradeFirm`,
  встроенный HTTP-апдейтер на ESP8266).
- **Обнаружение устройств по multicast-UDP**: устройства каждые 60 секунд
  рассылают broadcast-презентацию в группу `239.255.255.255:4210` в формате
  JSON-массива, например `[{"ip":"192.168.1.50","wg":"main","name":"..."}]`.
- **Модульная система**: подключаемые модули четырёх типов —
  `exec` (исполнительные), `sensors` (сенсоры), `display` (дисплеи),
  `virtual` (виртуальные элементы).
- **Сценарии** — настраиваемая логика устройства (класс `IoTScenario`).
- **Виртуальные элементы интерфейса** (кнопки, переменные, переменные-цвета,
  таймеры, Cron, логирование и т.д.) — существуют только в интерфейсе управления.
- **Сенсоры и периферия** по I²C, UART, ADC, SPI и дискретным пинам (в зависимости
  от набора активных модулей).
- **Telegram-уведомления** (модули `TelegramLT`, `Telegram_v2`).
- **FTP-доступ** к файловой системе устройства (модуль `Ftp`).
- **Веб-панель magicIoTm**: управление проектами и категориями, настройка
  `iotmSettings`, включение/выключение модулей, валидация параметров, контроль
  совместимости платформ, индикатор заполнения flash, сборка прошивки, экспорт/импорт
  конфигурации, сканирование сети и менеджер устройств (чтение/запись конфигурационных
  файлов).

## 3. Архитектура

### Структура репозитория

| Путь | Назначение |
|------|------------|
| `src/` | Исходный код прошивки: `Main.cpp`, классы `IoT*` (`src/classes/`), утилиты (`src/utils/`), модули (`src/modules/`) |
| `include/` | Заголовочные файлы прошивки (`*.h`) и классов |
| `lib/` | Внешние библиотеки: `LT_WebSockets`, `MySensors`, `PicoMQTT`, `SimpleFTPServer`, `WebSockets` |
| `data_svelte/` | Каталог данных (LittleFS) прошивки: веб-интерфейс, `config.json`, `items.json`, `settings.json`, `layout.json`, `ota.json` и др. |
| `data_full/`, `data_lite/` | Альтернативные комплекты веб-данных |
| `iotm/` | Готовые собранные прошивки по платформам и версиям (firmware/littlefs/partitions .bin) |
| `tools/` | Инструменты: `magicIoTm/` (веб-панель), `measure_size/` (замер размера), скрипты патчей и подготовки (`patch32_ws.py`, `prebuildscript.py`, `PrepareProject.py`) |
| `platformio.ini` | Конфигурация сборки PlatformIO (все целевые окружения) |
| `myProfile.json` | Персональная конфигурация пользователя (шаблон) |
| `bin/` | Готовые загрузчики (bootloader) для ESP32 |

### Модульная система (`src/modules/`)

Каждый модуль лежит в своей папке и содержит `modinfo.json` (описание: категория
меню, конфигурируемый элемент, автор, версия, используемые библиотеки по
платформам, размер flash/RAM по окружениям) и файл(ы) реализации `.cpp`.
Типы модулей:

- `exec` — исполнительные устройства (кнопки, ШИМ, термостат, Telegram, FTP, ИК-приёмник и др.);
- `sensors` — сенсоры (BME280, BMP280, DHT, DS18B20, NTC, PZEM, MH-Z19, SDS011 и др.);
- `display` — дисплеи (например Nextion);
- `virtual` — виртуальные элементы интерфейса (кнопка, переменные, таймер, Cron, погода, логирование и др.).

### Ключевые классы прошивки (`src/classes/`)

Назначение описано по названию и роли в коде (без глубокого разбора):

- `IoTItem` — базовый класс элемента конфигурации (каждого подключённого устройства/элемента).
- `IoTDB` — база данных элементов/конфигурации.
- `IoTGpio` — работа с GPIO (digital/analog/PWM).
- `IoTScenario` — управление сценариями (логика «событие → реакция»).
- `IoTDiscovery` — обнаружение устройств в сети.
- `IoTBench` — измерения производительности задач элементов.
- `IoTUart` — работа с UART.
- `NotAsync` — вспомогательный класс (синхронный слой).

Прошивка построена по цикличной модели: в `Main.cpp` функция `elementsLoop()`
последовательно передаёт управление каждому элементу конфигурации, обрабатывает
заказы (`handleOrder()`) и события (`handleEvent()`).

## 4. Как установить и запустить

### Требования

- **Для сборки прошивки:** PlatformIO (VSCode + расширение PlatformIO или CLI).
- **Для веб-панели magicIoTm:** Python (папка `.venv/` в корне), зависимости из
  `requirements.txt` (`flask>=3.0`, `flask-cors>=4.0`).

### Сборка прошивки (PlatformIO)

Конфигурация окружений находится в `platformio.ini`. Поддерживаемые окружения
(`default_envs` — `esp32s2_4mb`):

- ESP8266: `esp8266_1mb`, `esp8266_1mb_ota`, `esp8266_2mb`, `esp8266_2mb_ota`,
  `esp8266_4mb`, `esp8266_16mb`, `esp8285_1mb`, `esp8285_1mb_ota`;
- ESP32: `esp32_4mb`, `esp32_4mb3f`, `esp32_16mb`, `esp32cam_4mb`, `esp32s2_4mb`,
  `esp32c3m_4mb`, `esp32s3_16mb`, `esp32_wifirep`, `esp32c6_4mb`, `esp32c6_8mb`;
- BK7231N: `bk7231n` (LibreTiny, имя прошивки `iotm_tiny`).

Типовые шаги сборки вручную (для конкретного окружения, например `esp32_4mb`):

1. Подготовить проект: `python PrepareProject.py -p myProfile.json`.
2. Собрать файловую систему: `pio run -t buildfs -e esp32_4mb`.
3. Собрать прошивку: `pio run -e esp32_4mb`.
4. Записать на устройство (по USB/сети).

*(Более подробная инструкция по конкретной команде — в документации PlatformIO.)*

### Запуск веб-панели magicIoTm

Из каталога `tools/magicIoTm/`:

```
run.bat        # запуск сервера (python app.py)
restart.bat    # перезапуск
stop.bat       # остановка
```

Либо вручную:

```bat
cd tools\magicIoTm
pip install -r requirements.txt
python app.py
```

Сервер доступен по адресу: **http://127.0.0.1:5005**.

### Прошивка устройства через панель

Обычный рабочий цикл в панели magicIoTm:

1. Открыть проект (автоматически открывается последний открытый проект).
2. Подготовить проект к сборке — этап **«Подготовка профиля (PrepareProject)»**.
3. **Сборка**: сначала «Сборка файловой системы (buildfs)», затем
   «Сборка прошивки (build)».
4. Подключиться к устройству (см. раздел «Устройства» ниже).
5. Записать файловую систему (FS) и/или прошивку на устройство (кнопка «🚀 Upload»).

## 5. Использование веб-панели magicIoTm (основные разделы)

Панель — одностраничное приложение (SPA) с боковой панелью и основной областью.

### Сайдбар: «Проекты» и «Устройства»

- **📁 Проекты** — дерево категорий и проектов. Кнопки «+ Категория» и «+ Проект».
  Управление: создание, переименование, копирование, перенос, удаление (с
  автоматическим резервным копированием перед удалением).
- **💡 Устройства** — кнопка «🔍» сканирует сеть (поиск ESP-устройств пингованием
  и проверкой `/devlist.json`). Устройство можно добавить вручную по IP-адресу.

### Панель проекта

- **Платформа** — выбор целевой платформы; при смене платформы несовместимые
  модули автоматически отключаются.
- **Настройки устройства** — редактирование `iotmSettings` (имя устройства, группа
  WG, точка доступа AP, параметры роутера, MQTT-сервер, NTP, I²C и др.); значения
  можно скопировать из другого проекта.
- **💠 Модули** — список модулей по секциям с чекбоксами включения/выключения;
  групповое управление. Совместимость модулей с платформой подсвечивается.
- **Индикатор памяти** — расчёт заполненности прошивки (flash) на основе данных
  из `modinfo.json`.
- **⚖️ Замер размера** — измерение прироста размера прошивки по модулям:
  «Все модули», «Модули профиля», «Без размера» (для текущей платформы).
- **🔨 Сборка** — запуск сборки с поэтапным логом: 1) подготовка профиля
  (PrepareProject), 2) сборка FS (buildfs), 3) сборка прошивки (build). Показываются
  расчёты размера Flash/RAM/FS. Поток событий отдаётся по SSE.
- **🚀 Загрузка (Upload)** — запись прошивки/ФС на устройство.

### Менеджер устройств

При обнаружении устройства по multicast-UDP для него в папке `devices/` создаётся
подпапка `<SSID_ноутбука>_<ip>_<name>/` с разделами `RAM/` и `FS/`. Имя папки
использует SSID Wi-Fi-сети ноутбука (определяется через `netsh wlan show
interfaces`, fallback — `NET`).

Клик по устройству открывает менеджер с разделами:

- **RAM** — кнопка «⤵ Получить файлы» скачивает конфигурационные файлы по
  WebSocket-командам `/config|` и `/profile|` (порт 81):
  `items.json`, `widgets.json`, `config.json`, `scenario.txt`, `settings.json`
  (из `/config|`), а также `ota.json`, `profile.json` (из `/profile|`).
  Слева — дерево файлов, справа — редактор с подсветкой синтаксиса. Кнопка
  «💾 Сохранить» для `config.json`, `scenario.txt`, `settings.json` отправляет
  содержимое обратно на устройство через обратные WS-команды `/gifnoc|`,
  `/oiranecs|`, `/sgnittes|`, одновременно обновляя локальную копию; для остальных
  файлов запись на устройство недоступна.
- **FS** — раздел файловой системы устройства. Кнопка «⤵ Получить файлы»
  рекурсивно скачивает файлы по HTTP (порт 80) через эндпоинты прошивки
  (`/list?dir=` и `/<path>?download=1`). Слева — дерево файлов, справа — редактор.
  Кнопка «💾 Сохранить» сохраняет изменённый файл локально в папку устройства
  (обратной записи на устройство для FS нет).

### Экспорт/импорт

- Экспорт текущей конфигурации в JSON.
- Импорт базового конфига `myProfile.json` из корня репозитория как шаблона.
- Копирование `iotmSettings` и `modules` из других проектов.

## 6. Конфигурация и файлы данных

### Данные прошивки (`data_svelte/`)

| Файл | Назначение |
|------|------------|
| `config.json` | Базовая конфигурация элементов (в примере — пустой массив) |
| `items.json` | Список элементов конфигурации с заголовками секций (`executive_devices`, `screens`, `sensors`, `virtual_elments`); каждый элемент описывает тип, подтип, виджет, страницу, описание, пин, параметры |
| `settings.json` | Настройки устройства: имя, группа WG, точка доступа (SSID/пароль), параметры роутера, MQTT (сервер/порт/префикс/пользователь/пароль), NTP, I²C (частоты, пины), таймзона, web-логин/пароль, настройки Wi-Fi-репитера |
| `layout.json` | Раскладка виджетов на веб-странице |
| `values.json` | Значения элементов |
| `ota.json` | Настройки/состояние OTA-обновления |
| `flashProfile.json` | Профиль flash (параметры записи) |
| `index.html`, `favicon.ico`, `edit.htm.gz`, `build/` | Веб-интерфейс устройства и его ресурсы |

### Профиль пользователя

- `myProfile.json` (в корне) — персональная конфигурация: секция `iotmSettings`
  (те же параметры, что в `settings.json`) и секция `modules` — список активных
  модулей с путями (`src/modules/...`) и флагом `active`. Является шаблоном для
  создания проектов в magicIoTm.

### Проекты magicIoTm (`tools/magicIoTm/projects/`)

Структура `projects/[категория]/[проект]/`:

- `myProfile.json` — полная конфигурация (копия из корня при создании проекта);
- `data.json` — метаданные проекта;
- `about.txt` — описание проекта;
- `data_svelte/` — каноническая папка данных прошивки проекта (LittleFS), всегда
  расположена в корне проекта; заполняется `PrepareProject.py` из `data_full/`/`data_lite/`
  (файлы прошивки заменяют существующие) с сохранением пользовательских конфигов
  (`settings.json`, `items.json`, `flashProfile.json` и др.);
- `iotm/<платформа>/400/` — собранная прошивка (firmware/littlefs/partitions `.bin`);
  после успешной сборки в `iotm/` остаётся только одна папка с прошивками (текущей платформы).

### Сборка (PlatformIO)

- `platformio.ini` — все окружения, библиотеки (`ArduinoJson @6.18.0`,
  `PubSubClient` и др.), флаги сборки, скрипты предобработки, параметры
  filesystem = `littlefs`, data_dir = `data_svelte`.

### Инструменты

- `tools/measure_size/` — скрипт замера прироста размера прошивки по каждому
  модулю; результат пишется в `about.size` в `modinfo.json` (КБ по окружениям).
  Запуск: `measure_size/venv/bin/python measure_size/measure.py --env <env>`.

## 7. Ограничения и известные риски

Изложено кратко, как пользовательское предупреждение (на основе проведённого
аудита кода).

- **Аутентификация**: в локальной веб-панели magicIoTm не предусмотрен вход по
  паролю (зависимость `flask-cors` подключает CORS без ограничений). Панель
  предназначена для использования на доверенной машине.
- **CORS открыт**: HTTP-заголовки позволяют обращение с других источников, что
  следует учитывать при доступе к панели вне доверенной локальной сети.
- **Пути к файлам** (`path traversal`): операции чтения/записи файлов устройств
  работают с пользовательскими путями — при использовании инструмента не
  открывайте его для недоверенных клиентов.
- **Стабильность**: прошивка зависит от качества Wi-Fi, питания и конкретного
  контроллера; возможны перезагрузки/переподключения при нестабильной сети.
- **Устройства в локальной сети**: обнаружение и запись конфигурации происходят
  по незащищённым WebSocket/UDP-каналам — используйте панель в доверенной сети.

> Это пользовательский документ; полный список архитектурных ограничений и
> рекомендаций по безопасному развёртыванию — вне его рамок *(уточнить при необходимости)*.

## 8. Частые вопросы / подсказки

- **Порты.** Веб-панель magicIoTm — `127.0.0.1:5005`. Веб-интерфейс самого
  устройства — HTTP-порт `80`; WebSocket-сервер устройства — порт `81`.
  Встроенный MQTT-брокер (модуль `BrokerMQTT`) — порт по умолчанию `1883`.
  Multicast-UDP обнаружение — группа `239.255.255.255`, порт `4210`
  (пакеты каждые 60 секунд).
- **Сетевые протоколы.** Основной протокол обмена в вебе — WebSocket (для
  устройства также `DeviceList`/multicast-UDP). Обмен с облаком и приложением —
  через MQTT. OTA-обновление — по HTTP(S).
- **Кириллица в путях.** Упоминание ограничений по кириллице в путях в
  прочитанных README не найдено — *не найдено в документации* (при работе с путями
  к проектам рекомендуется использовать латиницу, пока вопрос не уточнён).
- **Имя устройства.** Уникальное имя устройства ограничено 16 символами и не
  должно содержать пробелов (валидация в панели). AP SSID также должен быть
  уникальным.
