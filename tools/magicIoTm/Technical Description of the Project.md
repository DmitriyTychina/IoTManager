# Technical Description — Веб-инструмент magicIoTm

> Пользовательская техническая документация веб-панели **magicIoTm** (папка
> `tools/magicIoTm`). Описаны только те функции и факты, которые подтверждены
> в коде панели и её `README.md`. Там, где информация отсутствует, стоит пометка
> *(уточнить)* или *не найдено в документации*.

---

## 1. Обзор

**magicIoTm** — локальная веб-панель (Python **Flask**) для конфигурации проектов
прошивки IoT-устройств (**ESP8266 / ESP32** и совместимых платформ) и управления
устройствами. Панель является инструментом репозитория IoTManager и располагается
в папке `tools/magicIoTm`.

Основное назначение панели:

- **Сборка прошивок через PlatformIO** — подготовка проекта, сборка файловой
  системы (buildfs) и самой прошивки (build) с поэтапным SSE-логом и расчётом
  размеров Flash/RAM/FS.
- **Управление проектами** — категории и проекты: создание, переименование,
  копирование, перенос, удаление (с автоматическим резервным копированием).
- **Конфигурация прошивки** — редактирование `iotmSettings`, включение/выключение
  модулей, валидация параметров, проверка совместимости платформ.
- **Замер размеров** — расчёт заполненности прошивки и прироста размера по модулям.
- **Работа с устройствами** — обнаружение устройств по **UDP multicast**,
  сканирование сети, чтение/запись конфигурационных файлов устройства по
  **WebSocket/HTTP**.

Сервер запускается локально на порту **5005** и работает через браузер.
Панель предназначена для использования на доверенной машине.

## 2. Возможности

Подтверждено кодом панели и `README.md`:

- **Управление проектами**: дерево категорий и проектов, создание/удаление/
  переименование/копирование/перенос.
- **Конфигурация**: редактирование `iotmSettings`, управление модулями через
  чекбоксы.
- **Валидация**: уникальность имени устройства (макс. 16 символов, без пробелов),
  уникальность AP SSID.
- **Совместимость платформ**: автоматическое отключение несовместимых модулей при
  смене платформы.
- **Индикатор памяти**: расчёт заполненности прошивки на основе `modinfo.json`.
- **Копирование настроек**: импорт `iotmSettings` и `modules` из других проектов.
- **Резервное копирование**: автоматический бэкап перед удалением.
- **История**: автооткрытие последнего проекта при запуске.
- **Экспорт/импорт**: выгрузка конфигурации в JSON; импорт базового конфига
  `myProfile.json` как шаблона.
- **Сборка**: подготовка профиля (PrepareProject), сборка FS (buildfs) и прошивки
  (build) с SSE-потоком событий.
- **Замер размера**: «Все модули», «Модули профиля», «Без размера».
- **Менеджер устройств**: обнаружение по multicast-UDP, скачивание файлов RAM
  с устройства (WS-команды `/config|` и `/profile|`) и запись изменённых файлов
  обратно (обратные WS-команды `/gifnoc|`, `/oiranecs|`, `/sgnittes|`).

## 3. Архитектура и структура

### Структура панели

| Путь | Назначение |
|------|------------|
| `app.py` | Flask backend: маршруты `/api/*`, сетевой слой (multicast, ping, HTTP), глобальное состояние, фоновые потоки/SSE |
| `index.html` | Frontend (SPA, vanilla JS) — боковая панель, редакторы, менеджер устройств |
| `README.md` | Документация панели |
| `run.bat` / `restart.bat` / `stop.bat` | Запуск / перезапуск / остановка сервера |
| `requirements.txt` | Зависимости (`flask>=3.0`, `flask-cors>=4.0`) |
| `favicon.png` | Иконка панели |
| `projects/` | Проекты пользователя (gitignored): `[категория]/[проект]/` |
| `devices/` | Папки устройств, обнаруженных по multicast-UDP |
| `utils/` | Логика: `projects.py`, `build.py`, `PrepareProject.py`, `measure_run.py`, `ws_client.py` |

### Ключевые модули (`utils/`)

- `projects.py` — управление категориями/проектами, валидация, бэкапы.
- `build.py` — сборка прошивки через subprocess PlatformIO, чтение размеров.
- `PrepareProject.py` — подготовка проекта к сборке (правка `platformio.ini`,
  генерация `API.cpp`, копирование `data_svelte`).
- `measure_run.py` — запуск замера размеров через `measure.py`, потоковый прогресс.
- `ws_client.py` — WebSocket/HTTP-клиент к устройствам: `fetch_fs`, `write_file`,
  `fetch_ram`.

### Менеджер устройств (`devices/`)

При обнаружении устройства по multicast-UDP для него создаётся подпапка
`<SSID_ноутбука>_<ip>_<name>/` с разделами `RAM/` и `FS/`. Имя папки использует
SSID Wi-Fi-сети ноутбука (определяется через `netsh wlan show interfaces`,
fallback — `NET`).

Раздел **RAM**: кнопка «⤵ Получить файлы» скачивает по WebSocket (порт 81)
командами `/config|` и `/profile|` файлы `items.json`, `widgets.json`,
`config.json`, `scenario.txt`, `settings.json` (из `/config|`), а также `ota.json`,
`profile.json` (из `/profile|`). Слева — дерево файлов, справа — редактор
с подсветкой синтаксиса. Кнопка «💾 Сохранить» для `config.json`, `scenario.txt`,
`settings.json` отправляет содержимое обратно на устройство через обратные
WS-команды (`/gifnoc|`, `/oiranecs|`, `/sgnittes|`), одновременно обновляя
локальную копию; для остальных файлов запись на устройство недоступна.

Раздел **FS** — файловая система устройства. Кнопка «⤵ Получить файлы»
рекурсивно скачивает файлы по HTTP (порт 80) через эндпоинты прошивки
(`/list?dir=` и `/<path>?download=1`). Слева — дерево файлов, справа — редактор.
Кнопка «💾 Сохранить» сохраняет изменённый файл локально в папку устройства
(обратной записи на устройство для FS нет).

## 4. Как установить и запустить

### Требования

- Python (рекомендуется виртуальное окружение), зависимости из `requirements.txt`
  (`flask>=3.0`, `flask-cors>=4.0`).
- Для сборки прошивок — PlatformIO (CLI или VSCode + расширение).

### Запуск

Из каталога `tools/magicIoTm/`:

```
run.bat        # запуск сервера (python app.py)
restart.bat    # перезапуск
stop.bat       # остановка
```

Либо вручную:

```bat
cd tools\magicIoTm
pip install -r requirements.txt
python app.py
```

Сервер доступен по адресу: **http://127.0.0.1:5005**.

### Рабочий цикл

1. Открыть проект (автоматически открывается последний открытый проект).
2. Подготовить проект к сборке — этап **«Подготовка профиля (PrepareProject)»**.
3. **Сборка**: сначала «Сборка файловой системы (buildfs)», затем
   «Сборка прошивки (build)».
4. Подключиться к устройству (раздел «Устройства»).
5. Записать файловую систему (FS) и/или прошивку на устройство (кнопка «🚀 Upload»).

## 5. Использование веб-панели (основные разделы)

Панель — одностраничное приложение (SPA) с боковой панелью и основной областью.

### Сайдбар: «Проекты» и «Устройства»

- **📁 Проекты** — дерево категорий и проектов. Кнопки «+ Категория» и «+ Проект».
  Управление: создание, переименование, копирование, перенос, удаление.
- **💡 Устройства** — кнопка «🔍» сканирует сеть (пингование и проверка
  `/devlist.json`). Устройство можно добавить вручную по IP-адресу.

### Панель проекта

- **Платформа** — выбор целевой платформы; несовместимые модули отключаются
  автоматически.
- **Настройки устройства** — редактирование `iotmSettings` (имя, группа WG,
  точка доступа AP, параметры роутера, MQTT-сервер, NTP, I²C и др.).
- **💠 Модули** — список модулей по секциям с чекбоксами; групповое управление.
- **Индикатор памяти** — расчёт заполненности прошивки (flash) из `modinfo.json`.
- **⚖️ Замер размера** — прирост размера прошивки по модулям.
- **🔨 Сборка** — поэтапный лог (подготовка → buildfs → build), расчёты
  Flash/RAM/FS, SSE-поток.
- **🚀 Загрузка (Upload)** — запись прошивки/ФС на устройство.

### Экспорт/импорт

- Экспорт текущей конфигурации в JSON.
- Импорт базового конфига `myProfile.json` как шаблона.
- Копирование `iotmSettings` и `modules` из других проектов.

## 6. Конфигурация и файлы данных

### Проекты magicIoTm (`projects/`)

Структура `projects/[категория]/[проект]/`:

- `myProfile.json` — полная конфигурация (копия из корня при создании проекта);
- `data.json` — метаданные проекта;
- `about.txt` — описание проекта.

### Профиль пользователя

`myProfile.json` содержит секцию `iotmSettings` (параметры устройства, MQTT, NTP,
I²C и др.) и секцию `modules` — список активных модулей с путями и флагом `active`.
Является шаблоном для создания проектов в magicIoTm.

### Сборка (PlatformIO)

Сборка выполняется через `platformio.ini` (окружения, библиотеки, флаги,
`filesystem = littlefs`, `data_dir = data_svelte`).

## 8. Ограничения и известные риски

Изложено кратко, как пользовательское предупреждение (на основе проведённого
аудита кода).

- **Аутентификация**: в панели не предусмотрен вход по паролю (зависимость
  `flask-cors` подключает CORS без ограничений). Панель предназначена для
  использования на доверенной машине.
- **CORS открыт**: HTTP-заголовки позволяют обращение с других источников —
  учитывайте при доступе к панели вне доверенной локальной сети.
- **Пути к файлам** (`path traversal`): операции чтения/записи файлов устройств
  работают с пользовательскими путями — не открывайте панель для недоверенных
  клиентов.
- **Устройства в локальной сети**: обнаружение и запись конфигурации происходят
  по незащищённым WebSocket/UDP-каналам — используйте панель в доверенной сети.

> Это пользовательский документ; полный список архитектурных ограничений и
> рекомендаций по безопасному развёртыванию — вне его рамок *(уточнить при необходимости)*.

## 9. Частые вопросы / подсказки

- **Порт.** Панель magicIoTm — `127.0.0.1:5005`.
- **Обнаружение устройств.** Multicast-UDP группа `239.255.255.255`, порт `4210`
  (пакеты каждые 60 секунд).
- **Сетевые протоколы.** Основной протокол обмена с устройствами — WebSocket
  (чтение/запись конфигурации). Обнаружение — multicast-UDP.
- **Имя устройства.** Уникальное имя устройства ограничено 16 символами и не
  должно содержать пробелов (валидация в панели). AP SSID также должен быть
  уникальным.
- **Не знаете, где лежит конфигурация проекта?** Конфигурация конкретного
  проекта magicIoTm — в `projects/<категория>/<проект>/myProfile.json`.

### Контекст (прошивка IoTManager)

Панель magicIoTm управляет прошивкой IoTManager — системой «умного дома» на
**ESP8266 / ESP32**. Прошивка подключается к домашнему Wi-Fi, управляет периферией
(сенсоры, реле, двигатели и т.д.), настраивается сценариями и поддерживает
MQTT, OTA, локальный веб-интерфейс и модульную систему
(`exec`, `sensors`, `display`, `virtual`). Подробности прошивки описаны в корне
репозитория IoTManager — здесь они приведены кратко как контекст использования
панели.
