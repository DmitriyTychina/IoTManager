# MagicIoTm — Конфигуратор прошивок IoTmanager

Web-приложение на Python Flask для управления проектами и конфигурациями IoT-устройств (**ESP8266 / ESP32**). Запустите `run.bat` и откройте http://127.0.0.1:5005 — панель найдёт устройства с IoTmanager-прошивкой в локальной сети, позволит настроить и собрать прошивку (**PlatformIO**), записать её по **USB** или **OTA** и редактировать конфигурацию устройства.

Предложения приветствуются.

## Возможности

- **Управление проектами**: категории и проекты — создание/удаление/переименование/копирование/перенос. Защищённый проект **PlatformIO** работает напрямую с корневым `myProfile.json` и `platformio.ini` (его нельзя переименовать, перенести или удалить). Автоматический бэкап в `projects/.backups` перед удалением, автооткрытие последнего проекта при запуске.
- **Конфигурация**: редактирование `iotmSettings`, управление модулями через галочки (`active`), копирование `iotmSettings`/`modules` из других проектов, импорт базового конфига из корневого `myProfile.json` в текущий проект, экспорт конфигурации в JSON.
- **Валидация**: имя устройства — не более 16 символов, без пробелов, уникально в пределах всех проектов (включая корневой PlatformIO); AP SSID — уникален (может быть пустым).
- **Платформы**: выбор целевой платформы из `[env:*]` секций `platformio.ini`; при смене платформы несовместимые модули отключаются автоматически (совместимость определяется по `usedLibs` в `modinfo.json`).
- **Индикаторы памяти (гайджи)**: расчёт заполненности **FLASH** / **RAM** / **FS** на основе `modinfo.json` (размеры модулей по платформам) и `platforms.json` (baseline/total).
- **Сборка**: подготовка профиля (`PrepareProject.py`) → сборка файловой системы (`buildfs`) → сборка прошивки (`build`) с поэтапным SSE-логом и расчётом размеров Flash/RAM/FS; после успешной сборки ёмкость FS (`total_fs`) сохраняется в `platforms.json`.
- **Замер размеров**: запуск `measure_size/measure.py` в фоне с несколькими режимами: все модули / отдельный модуль / базовая прошивка / профиль / без размера; SSE-прогресс, мягкое прерывание, автоматическое обновление кэшей `modinfo`/`platforms` после завершения.
- **Прошивка по USB**: проверка/автоустановка/обновление **esptool** на старте и по запросу, определение подключённого ESP-чипа (модель, семейство, объём flash), режимы записи — только FS / только прошивка / полная прошивка; защита: если flash чипа меньше требуемого для платформы — прошивка отменяется.
- **OTA**: прошивка по воздуху — режимы `firmware` / `fs` / `full`, способ записи FS — образ (`flash`, `littlefs.bin`/`spiffs.bin`) или пофайловая загрузка `data_svelte` (`copy`); локальный HTTP-сервер `.bin`, проверка совпадения платформы устройства и проекта, список совместимых онлайн-устройств.
- **Менеджер устройств**: обнаружение по UDP-multicast (239.255.255.255:4210), фоновый пинг, сканирование сети с выбором сетевого интерфейса, добавление устройства вручную по IP, разделы **RAM** и **FS** (дерево файлов + редактор с подсветкой), скачивание файлов с устройства с прогрессом, локальное сохранение изменений, копирование `settings.json`/`profile.json` с устройства в проект, удаление устройств (папка + записи).
- **Статусы устройств (цветная точка)**: 🟢 зелёный / ⚪ серый / 🟡 жёлтый / 🔴 красный — конечный автомат (детали ниже).
- **Проверка scenario.txt**: кнопка «🔍 Проверка» в редакторе — анализ скобок, конструкции if/then/else, циклических зависимостей переменных, неизвестных переменных относительно `config.json`, встроенных функций вида `ID.функция()` (по `modinfo.json`/`sceninfo.json`).

## Статусы устройств (цветная точка)

Статус определяется конечным автоматом (`_next_state` в `core/devices.py`) и привязан к папке устройства `<имя> <id>`. **Пинг сам по себе зелёный не даёт** — требуется совпадение имени и id устройства (multicast или `settings.json`).

| Цвет | Значение |
|------|----------|
| 🟢 Зелёный | Свежий multicast-пакет с совпадением имени и id устройства **ЛИБО** успешный пинг + актуальный `settings.json` с совпадением имени и id |
| ⚪ Серый | Статус не подтверждён: пинг успешен, но multicast не приходил / имя+id не совпадают, или данных нет |
| 🟡 Жёлтый | 1–3 провала пинга **после зелёного** (multicast не обновлялся) |
| 🔴 Красный | Более 3 провалов пинга (только после жёлтого) |

Ключевые правила:

- Жёлтый/красный достижимы **только после зелёного**; из серого в жёлтый/красный перейти нельзя.
- Повторное подтверждение (multicast или пинг+settings) сразу возвращает зелёный.
- Успешный пинг без подтверждения переводит зелёный/жёлтый/красный в серый.
- **Живой multicast авторитетен**: при свежем multicast пинг/`settings.json` не выполняются (на разделяемом IP settings может вернуть имя другого устройства).
- Пинг выполняется **один раз на уникальный IP**; если папок на одном IP несколько — он проверяется единожды.
- На одном IP зелёным может быть **только одно устройство** (`_enforce_single_green`).
- После свежего multicast устройство не пингуется 70 секунд (`PING_SKIP_AFTER_MULTICAST=70`).
- Во время скачивания файлов (`fetch` RAM/FS) пинг и WS-запросы к этому IP приостанавливаются (`_device_busy_fetching`), чтобы не срывать передачу.
- Имена устройств в вебе показываются без изменений (подчёркивания сохраняются).

## Менеджер устройств

При обнаружении устройства по multicast-рассылке (UDP, группа 239.255.255.255, порт 4210) для него в папке `magicIoTm/devices` создаётся папка:

```
<имя_устройства> <id>/           # если есть id
<имя_устройства> <ip>/          # если id пуст
├── RAM/    # скачанные с устройства конфигурационные файлы
└── FS/     # файловая система устройства
```

При клике на устройство в сайдбаре открывается менеджер: верхняя строка кнопок, ниже — разделы **RAM** и **FS**. В каждом разделе — кнопка «⤵ Получить файлы», дерево файлов слева и редактор выбранного файла справа (с подсветкой синтаксиса, номерами строк).

### Раздел RAM

Кнопка «⤵ Получить файлы» скачивает файлы с устройства по WebSocket-командам `/config|` и `/profile|` (порт 81, аналогично `tools/ws_cmds.py`):

| Файл в папке RAM | Источник |
|------------------|----------|
| items.json, widgets.json, config.json, scenario.txt, settings.json | `/config\|` |
| ota.json, profile.json | `/profile\|` |

Редактор позволяет:

- «💾 Локально» — сохранить изменения в локальную копию (папку устройства).
- «💾 На устройство» — отправить файл обратно через обратные WS-команды. Прошивка поддерживает запись **только** для `config.json` (`/gifnoc|`), `scenario.txt` (`/oiranecs|`), `settings.json` (`/sgnittes|`); также поддерживается `layout.json` (`/tuoyal|`) и `devlist.json` (`/tsil|`). Файл больше 50 КБ одним фреймом записать нельзя.

При скачивании отображается прогресс (кнопка «Получить файлы» → модальный прогресс «Получение файлов RAM»).

### Раздел FS

Кнопка «⤵ Получить файлы» рекурсивно скачивает файловую систему устройства по **HTTP** (порт 80): перечисление каталогов через `/list?dir=<path>`, скачивание файлов через `/<path>?download=1`. Редактор позволяет сохранить изменения **локально** (обратной записи на устройство для FS нет).

### Прочие действия

- Кнопка **✕** у устройства в списке — удалить папку с файлами и все записи об устройстве (при занятости папки удаление откладывается в фоновый поток).
- Кнопка **🔁** — перезагрузка устройства по WS (`/reboot|`).
- «Добавить устройство» — регистрация устройства по IP вручную.
- Копирование настроек/модулей: `settings.json` (RAM/FS) или `profile.json` (RAM) / `flashProfile.json` (FS) с устройства в открытый проект (раздел «Настройки»/«Модули»).

### Сканирование сети

Кнопка «🔍» в сайдбаре: отображается список доступных сетевых интерфейсов (реальные IP; исключаются loopback 127.x.x.x и link-local 169.254.x.x; для Wi-Fi показывается SSID). Доступна кнопка «Сканировать все подсети» (`__all__`). Сканирование выполняется в фоне пингованием (до 64 параллельно), найденные устройства автоматически добавляются. Прогресс — по SSE.

## Проверка scenario.txt

Кнопка «🔍 Проверка» в редакторе выполняет несколько видов анализа:

- **Скобки**: баланс `{}`, `()`, `[]` с указанием строк и позиций непарных скобок (комментарии `#` и строки игнорируются).
- **if/then/else**: наличие пар if-then, корректность конструкции, обнаружение then/else без if (рекурсивный разбор с учётом вложенности `{}`).
- **Зацикливание (event-driven)**: анализ циклических зависимостей между переменными.
- **Переменные в config.json**: загрузка `config.json` **из той же папки, где лежит проверяемый scenario.txt**, извлечение ID элементов по полю `"id"`, сравнение с переменными сценария, список неизвестных переменных.
- **Встроенные функции**: проверка вызовов `ID.функция()` — функция ищется строго по модулю элемента (по `subtype` в `config.json`) в `about.funcInfo[].name` файлов `modinfo.json`, плюс зарезервированные имена из `src/modules/sceninfo.json`; неизвестные функции выводятся по строкам.

Списки функций для проверки отдаёт API `GET /api/scenario/functions` (`reserved` + `bySubtype`).

## Ограничения и примечания

- Панель — локальный инструмент без аутентификации; CORS открыт, **path traversal** в путях файлов возможен. Используйте на доверенной машине и в доверенной сети, не открывайте доступ для недоверенных клиентов.
- Панель работает на **Windows** (скрипты `.bat`, `netsh` для SSID, `ping -n`). На Unix сборка/прошивка работают, но часть утилит адаптирована под Windows.
- Замер и сборка не могут выполняться одновременно (взаимная блокировка в API).
- Размер файла для записи на устройство ограничен 50 КБ (один WebSocket-фрейм ESP).
