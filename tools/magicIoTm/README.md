# MagicIoTm — Конфигуратор прошивок IoTmanager

Web-приложение на Python Flask для управления проектами и конфигурациями IoT-устройств.

## Возможности

- **Управление проектами**: категории, создание/удаление/переименование/копирование
- **Конфигурация**: редактирование iotmSettings, управление модулями через галочки
- **Валидация**: уникальность имени устройства (макс. 16 символов, без пробелов), уникальность AP SSID
- **Совместимость платформ**: автоматическое отключение несовместимых модулей при смене платформы
- **Индикатор памяти**: расчёт заполненности прошивки на основе данных из modinfo.json
- **Копирование настроек**: импорт iotmSettings и modules из других проектов
- **Резервное копирование**: автоматический бэкап перед удалением
- **История**: автооткрытие последнего проекта при запуске
- **Экспорт**: выгрузка конфигурации в JSON
- **Импорт базового конфига**: загрузка myProfile.json из корня проекта как шаблона
- **Менеджер устройств**: клик по устройству в списке открывает панель управления с разделами RAM и FS (дерево файлов + редактор), скачивание файлов RAM с устройства (WS-команды `/config|` и `/profile|`) и запись изменённых файлов обратно на устройство
- **Единое выделение в сайдбаре**: активный пункт подсвечивается в одном из деревьев — PlatformIO, проекты или устройства
- **Статусы устройств (цвет точки)**: 🟢 зелёный — свежий multicast-пакет с совпадением имени и id устройства ЛИБО успешный пинг + актуальный `settings.json` с совпадением имени и id; ⚪ серый — статус не подтверждён (нет multicast и/или `settings.json` не совпадает); 🟡 жёлтый — 1–3 провала пинга после зелёного; 🔴 красный — более 3 провалов пинга
- **Фоновый пинг устройств**: раз в 60 секунд проверяются устройства; статус привязан к папке `<имя> <id>` и определяется конечным автоматом (`_next_state`). Пинг сам по себе зелёный не даёт — требуется совпадение имени и id (multicast или `settings.json`). Жёлтый/красный достижимы только после зелёного. Пинг выполняется ОДИН раз на уникальный IP: если несколько устройств разделяют один адрес, он проверяется единожды. На одном IP зелёным может быть только одно устройство (`_enforce_single_green`). После свежего multicast устройство не пингуется 70 сек (`PING_SKIP_AFTER_MULTICAST=70`). Имена устройств в вебе показываются без изменений (подчёркивания сохраняются)
- **Пауза при скачивании файлов**: во время получения файлов с устройства (`fetch` RAM/FS) пинг и WS-запросы (в т.ч. загрузка `settings.json`) к этому IP приостанавливаются, чтобы не срывать передачу на однопоточном стеке ESP8266
- **Удаление устройств**: кнопка ✕ у устройства в списке (видна при наведении) удаляет папку с скачанными файлами и все записи об устройстве
- **Сканирование сети с выбором интерфейса**: перед сканированием отображается список всех доступных сетевых интерфейсов для выбора подсети. Фильтруются только интерфейсы с реальными IP (исключаются loopback 127.x.x.x и link-local 169.254.x.x). Для беспроводных интерфейсов показывается SSID сети (вместо системного имени «Беспроводная сеть»). Показывается тип сети (🏠 локальная / 🌐 внешняя). Доступна кнопка "Сканировать все подсети" для одновременного сканирования всех интерфейсов. Отмена выбора разблокирует кнопку сканирования.

## Запуск

```bat
run.bat
```

Сервер: http://127.0.0.1:5005

```

│   └── [категория]/
│       └── [проект]/
│           ├── myProfile.json   # Полная конфигурация (копия из корня при создании)

├── utils/
│   ├── projects.py     # Логика управления проектами
│   └── ws_client.py    # WebSocket-клиент для устройств (чтение/запись RAM)
```

## Менеджер устройств

При обнаружении устройства по multicast-рассылке (пакет UDP) для него в папке
`magicIoTm/devices` создаётся папка:

```
<имя_устройства> <id>/           # если есть id
<имя_устройства> <ip>/          # если id пуст
├── RAM/    # скачанные с устройства конфигурационные файлы
└── FS/     # раздел файловой системы (каркас, наполнение позже)
```

Имя папки формируется из имени устройства (из multicast-пакета), ID устройства
(из multicast-пакета) и IP-адреса. Разделитель — **пробел** (не `_`), чтобы символы `_`
внутри имени устройства не путались с границей имени и id/IP. Папка создаётся один раз
и не меняется при смене сети. Легаси-папки с разделителем `_` продолжают распознаваться
(без создания дублей).

При клике на устройство в сайдбаре в основной области открывается менеджер:
верхняя строка основных кнопок, ниже — разделы **RAM** и **FS**. В каждом разделе —
строка кнопок (кнопка «⤵ Получить файлы») и тело: дерево файлов слева и редактор
выбранного файла справа.

Кнопка «⤵ Получить файлы» в разделе **RAM** скачивает файлы с устройства по
WebSocket-командам `/config|` и `/profile|` (аналогично `tools/ws_cmds.py`):

| Файл в папке RAM | Источник |
|------------------|----------|
| items.json, widgets.json, config.json, scenario.txt, settings.json | `/config\|` |
| ota.json, profile.json | `/profile\|` |

Редактор позволяет сохранить изменения локально («💾 Локально»), а для файлов,
поддерживаемых прошивкой записи (config.json, scenario.txt, settings.json) — отправить
обратно на устройство («💾 На устройство») через обратные WS-команды
`/gifnoc|`, `/oiranecs|`, `/sgnittes|`.

> Раздел FS пока является каркасом интерфейса: папка FS пуста, скачивание файлов
> реализуется после добавления в прошивку команд листинга/чтения произвольных файлов.

## API

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/api/projects` | Дерево проектов |
| POST | `/api/projects/category` | Создать категорию |
| DELETE | `/api/projects/category/<name>` | Удалить категорию |
| POST | `/api/projects/create` | Создать проект |
| DELETE | `/api/projects/<cat>/<name>` | Удалить проект |
| POST | `/api/projects/<cat>/<name>/rename` | Переименовать |
| POST | `/api/projects/copy` | Копировать проект |
| POST | `/api/projects/move` | Перенести проект |
| POST | `/api/projects/<cat>/<name>/open` | Открыть проект |
| GET | `/api/projects/last` | Последний открытый |
| GET | `/api/projects/list-all` | Список всех (для копирования) |
| POST | `/api/projects/copy-settings` | Копировать iotmSettings |
| POST | `/api/projects/copy-modules` | Копировать modules |
| GET | `/api/config` | Текущая конфигурация |
| POST | `/api/config/save` | Сохранить конфигурацию |
| POST | `/api/config/settings` | Сохранить настройки |
| POST | `/api/config/about` | Сохранить описание |
| POST | `/api/config/import-root` | Импорт из ../myProfile.json |
| GET | `/api/config/export` | Экспорт в JSON |
| POST | `/api/modules/toggle` | Включить/выключить модуль |
| GET | `/api/modules/compatibility` | Совместимость модулей |
| POST | `/api/modules/info` | Информация о модуле |
| GET | `/api/platforms` | Список платформ |
| POST | `/api/platform/change` | Смена платформы |
| GET | `/api/size` | Размер прошивки |
| GET | `/api/validate/name` | Валидация имени |
| GET | `/api/validate/apssid` | Валидация AP SSID |
| GET | `/api/device/<ip>/info` | Инфо устройства и путь к папке |
| POST | `/api/device/<ip>/fetch/ram` | Получить файлы из RAM устройства |
| GET | `/api/device/<ip>/tree/<ram\|fs>` | Дерево файлов раздела |
| GET | `/api/device/<ip>/file/<ram\|fs>?path=` | Содержимое файла |
| POST | `/api/device/<ip>/file/<ram\|fs>` | Сохранить файл локально |
| POST | `/api/device/<ip>/write/ram` | Записать файл обратно на устройство |
| DELETE | `/api/device/<device_key>` | Удалить устройство (папка + записи) |
| GET | `/api/devices/interfaces` | Список сетевых интерфейсов |
| POST | `/api/devices/scan` | Запустить сканирование (опционально `{"subnet": "192.168.0.11"}`) |
| GET | `/api/devices/scan/stream` | SSE-поток прогресса сканирования |
